# 开发循环

从 journal 2026-08-02 实践日志提取的完整开发流程。步骤可能比一轮循环更多，循环里还有子循环（调用 code agent 去做）。

## 步骤

1. **先写文档** — 文档不一定要是 specification，打算怎么写就不需要那么严格；可以用 spec，但没必要过于严格
2. **设置测试** — 文档驱动、测试驱动比纯文档流程更严格一点，其实会更有用
3. **设计模块和测试实现** — 按文档与测试设计模块
4. **测试和代码实现**
5. **评审中不断整理和重构** — 评审时特别注意：先根据社区的规范来，然后再考虑最后怎么去写
6. **回到产品视角** — 结束技术开发之后，回到产品视角或用户视角看这个功能实现得怎么样。经常发现可能因为各种原因有一些偏差，及时发现、及时规划；回到产品/用户视角就知道人类该怎么去理解它

## 原则

- 非常强调**直接使用 AI 现有的知识**，而不是给它增加结构
- 通过不断**简化自己的习惯方式来适应 AI**，从而达到人机合作的状态
- 写各个语言的项目时，尽可能让他们遵循各个语言的规范，这是一个很重要的评审过程
