# 日志到 harness 修正

把 `data/journal/` 落档记录里的偏离标记，修成 `data/profile/` 各业务域的 harness 修订（loops、skills、prompts、agents）。修正没有终态：落地＝假设入档，不再偏＝暂时在位，再现偏离＝怀疑、证伪退位。

## 前置判据（缺了就不动）

1. **偏离字段**：记录里有「预期 X，实际 Y」的句子才选料；模糊的「AI 偏了」不选——没法比对就没法指认同任务形态；
2. **同任务形态**：按工作目录机械筛一遍相似 session，再比对偏离描述，对得上才算同一形态。形态不事前定义，靠描述指认；
3. **选料归 human**：AI 只交候选清单（哪条偏离、复现几次、在哪几个目录），修不修、先修哪条由人拍板。

## 流程

1. **扫偏离**：按域通读 `data/journal/{业务域}/`，把偏离字段逐条摘出，同描述的合并计数（跨目录也合并——适用范围绑偏离模式，不绑目录）；
2. **选落点**：`loops/`（重复出现的操作序列）→ `skills/`（可安装做法，带 references）→ `prompts/`（一次性措辞）→ `agents/`（系统配置，改机器上的工作配置，仓收快照）。落哪个域的目录看偏离发生在哪个业务域；
3. **落修订**：一处偏离一处修订；同一场景仓里只留一版在位，新版直接替换旧版，不并存；
4. **写适用场景**：写「创始人给定目标的场合」这种形态描述，不写「quanttide-meta 目录下」这种位置描述；
5. **假设入档**：修订旁标注两样——它修的是哪条偏离（域＋日期，指回日志）、它的证伪条件（什么实况会证明它没用）。没有证伪条件的修订不收；
6. **复现核验**：下次同类 session 跑完回看；再现偏离＝旧规则被拉出来怀疑，证伪就退位换新版，回到第 3 步。

## 边界

- **不凭印象选料**：挖掘知识经验不是本域的活，选料入口只有日志里的偏离字段；
- **日志仓不写「以后应该……」**：修正是本仓的事，日志只记偏离；
- **机器配置是采集源，仓是正本**：`~/.pi`、`~/.hermes` 的改动要回流成本仓的快照。

## 陷阱

- 写下「修好了」——本域没有这个词，修订永远在位待证伪；
- 同场景两版并存——快照式，替换不并存，取用只取在位的；
- 适用场景写成目录——目录会变，模式才是适用范围；
- 洞察没站住就批量修——「偏离成批出现」这类判断在 `data/insight`，它塌了修的顺序要重排。

## 验收

- 每条修订指得到它修的偏离记录（域＋日期，回日志查得到）；
- 同一场景仓里只有一版在位；
- 每条修订有写明的证伪条件；
- 证伪退位有记录（日志追加，不是抹掉）。

领域全景见领域仓 `domains/quanttide-agent/AGENTS.md`。
